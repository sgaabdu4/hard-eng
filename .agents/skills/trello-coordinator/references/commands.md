# Board commands + config

Load before running the script or editing `trello.json`.

## Secrets + state

- `.env.trello.local` in the main checkout holds `TRELLO_KEY` + `TRELLO_TOKEN`. Git must ignore it; the script refuses otherwise, and `save-secret` adds it to the local `info/exclude` when needed. A worktree reads the main checkout's file through `git rev-parse --git-common-dir`; never copy it.
- Key + token = the steps in [hosts](hosts.md#missing-key-or-token). The token reaches every board of its account.
- State, posted-comment log, run lease and the coordinator's handover note (`handover.md`: card → worker thread or worktree, card → what it waits for, open promises, test and demo accounts) live in `<git common dir>/trello-coordinator/`: never tracked, shared by worktrees on one machine.
- Claim = one machine runs the coordinator at a time. It is a parentless commit on `refs/trello-coordinator/claim` at `origin` (a ref, not a branch: it starts no workflow) that names the holding machine. `check` takes it only when none exists; every write command except a `--dry-run` is refused unless `origin`'s claim is this machine's own. A held claim never expires: only `takeover`, on the user's order on the new machine, moves it. A claim has no release command.
- Memory = the state folder's top-level `*.md`, `*.log` and `*.json` files (posted log, `state.json`, `handover.md`, worker notes). It travels in the claim commit only when `origin` is an `https://github.com/<owner>/<repo>` URL (with or without `.git`) and `gh repo view` says `PRIVATE`. In any other case, or when that check fails, no memory is sent: a new claim holds only the holder line (a random machine id and a time), and `finish` leaves the claim as it is. The key, token and run lease never travel. Before memory travels, `check`, `finish` and `takeover` refuse any memory file that holds the key or the token. Never write other keys, tokens or passwords in the state folder.
- Claim pushes skip the pre-push hook, because the claim holds no code to check. No other push skips it.
- Output, errors and logs never contain the key or token.

## `trello.json`

Repository root, tracked, no secrets (a key-like value is refused).

| Field         | Meaning                                                                                                                                                                                                                                             |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `board`       | Required. Board link or shortLink.                                                                                                                                                                                                                  |
| `account`     | Optional. Trello username the token must belong to; every write is refused for another account. Left out = the token's account.                                                                                                                     |
| `allowed`     | Optional. Left out = every board member's comments are requests, so a new member needs no setup. Set = only these usernames make requests. Everyone else = information.                                                                             |
| `lists`       | Optional. Role → list name: `todo`, `doing`, `testing`, `done` required; `urgent`, `discuss` optional. Left out = found by name (To do or Backlog, Doing or In progress, Testing or Review, Done, Urgent, Discuss).                                 |
| `needsLabels` | Username → label name, for example `"Needs Sam"`.                                                                                                                                                                                                   |
| `timing`      | Defaults in brackets: `everyMinutes` (15), `chaseHours` (24), `promiseHours` (6), `doneGraceHours` (72).                                                                                                                                            |
| `roles`       | Optional; left out = the default split in hosts. Role → `{"model", "why"}` plus optional `"provider"` (the host's provider id, for hosts that offer several) for `coordinator`, `builder`, `planner`, `reviewer`, `lookup`, optional `computerUse`. |
| `privacy`     | Optional extra regex list blocked in comments.                                                                                                                                                                                                      |

## Commands

`python3 .agents/skills/trello-coordinator/scripts/trello.py <command>`; `<card>` = card number (`#N` name prefix) or shortLink. `--dry-run` on any write command prints the planned requests and sends nothing; it needs no claim.

| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `probe`                                                                                | JSON `account`, `board`, `lists` (role, name, id), `labels`. Exit 1 when the account differs from `account` or a configured list is missing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `check`                                                                                | Starts the run lease, takes the claim on `origin` when none exists, and prints the JSON report below with its `runId`; never writes to Trello. Another machine holds the claim → prints `{"skipped": true, "heldElsewhere": true, "heldSince": <time>}`, reads nothing and ends the lease. `origin` unreachable, or a memory file holds the key or token while it takes the claim → `error`. ## `check` report

Each list holds `{card, name, list, url, at, author, excerpt}` items. "Our comment" = a comment whose id is in the posted log.

| Field         | Item                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `requests`    | Newest action after our newest comment is a comment (an edited comment counts at its edit time), image, description edit, card move or new card by a board member, or an `allowed` member when set. A short "ok" or "thanks" on a card in `done` is no request. Any age, on every open card; a card in `done` counts only until `doneGraceHours` after its move there.                                                |
| `information` | Same, by anyone else. Never a request.                                                                                                                                                                                                                                                                                                                                                                                |
| `owner`       | Newest action on the card is a comment, move or new card by the token's account that is not in the posted log (our `move` and `new` log theirs) and is newer than this machine's first `check`: the human owner. Stays listed until we reply. Act on it; never write over it.                                                                                                                                         |
| `promises`    | Our newest comment makes a promise, read as in [Promise words](#promise-words), and is older than `promiseHours`. Never for a card in `done`.                                                                                                                                                                                                                                                                         |
| `silent`      | An open question of ours is older than `chaseHours`, counted from the newest open question to that person, so a chase restarts the clock. Never for a person whose label is on a `testing` card (see `testQueue`).                                                                                                                                                                                                    |
| `buried`      | Open question of ours to a person that our newest comment does not tag again: ask it again in a new tagged comment. Not for a person whose label is on a `testing` card.                                                                                                                                                                                                                                              |
| `badTags`     | `@name` in our comments that is not a board member.                                                                                                                                                                                                                                                                                                                                                                   |
| `labels`      | `needsLabels` label with no open question to that person, or an open question with no label. Open question = any comment, ours or a board member's, that tags another member and asks something (`?`, please, reply, can you, could you, let me know), with no comment from that member after it. On a `testing` card, a labelled person tagged in our comment owes a test until they reply, so their label is right. |
| `waitsOnUs`   | Card in `testing` where our newest comment says the card waits on us, with one of these: "next release", "not built yet", "I am fixing", "I am building", "I am changing", "I will fix", "being built" or "waits for the #N fix". The same comment must not say the work is now live. Step 1 of [Promise words](#promise-words) applies first. The check only lists the card; the coordinator moves it.               |
| `testQueue`   | One item per person whose `needsLabels` label is on cards in `testing`: the count of those cards and the oldest one. Not chased on the cards.                                                                                                                                                                                                                                                                         |
| `unnumbered`  | Open card whose name lacks `#N`, or the newer of two open cards with the same `#N`. A `#N` that matches two cards is refused by every command: use the shortLink.                                                                                                                                                                                                                                                     |
| `overdue`     | Due date passed, card not in `done`.                                                                                                                                                                                                                                                                                                                                                                                  |
| `realCases`   | Open card with the `Waiting for real case` label: only a real user event can prove it.                                                                                                                                                                                                                                                                                                                                |
| `idle`        | Card in `todo`, `doing` or `urgent` with no comment or move for `chaseHours`. Its clock is the newest comment or move on the card; a card with neither uses the time it was made, read from its id. Sorting or labelling cards does not reset the clock. Excerpt: hours and list.                                                                                                                                     |

### Promise words

`promises` reads our newest comment in three steps. `waitsOnUs` uses step 1 too.

1. Two parts of each sentence are hidden. A sentence ends at ".", "!", "?" or a line break.
   - The first part starts at "if", "when", "once", "after", "until" or "before" and runs to the end of the sentence.
   - The second part is a question. It runs from the last comma or semicolon before the "?" to the "?". A question with no comma or semicolon is hidden whole.
2. Only the text after the last "is live", "are live", "is done", "are done" or "went live" that is still shown is read. "Now" or "already" may come between "is" or "are" and "live" or "done". With none of these, the whole comment is read.
3. Each of these makes a promise:
   - "I will", "I'll" or "Next:".
   - "I am" or "I'm" followed by one of: fixing, building, changing, adding, checking, making, watching, writing, looking, testing, updating, sending, posting, "going to".
   - "I" followed by one of: check, post, make, fix, send, add, update, tell, share, reply, look, watch, test.
   - "being built", "being fixed" or "waits for the #N fix".

So "I post here when it is live", "I will fix #13 once #12 is live" and "I'll post it tonight, can you test it?" are promises. "If it fails, I will look" and "Can I check it?" are not.
