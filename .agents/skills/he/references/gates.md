# Native gate contracts

- Python complexity = retain both native Ruff checks: `lint` enables C901/PLR0912/PLR0915 with project settings, and `complexity` explicitly caps complexity/branches/statements at 10/12/50. The first preserves stricter project limits; the second prevents relaxed configured thresholds from raising the agreed ceilings. Review exclusions and narrow exceptions separately; these commands do not certify scan scope or prevent removal from a project-owned manifest.

- Python dependency declarations = run deptry in the project's installed dependency environment, retaining `--no-ansi --json-output coverage/deptry.json` and report type `deptry`. The runner requires a fresh empty finding list and native diagnostics showing a nonempty source scan, and rejects skipped-source warnings: deptry 0.25.1 can skip malformed Python while returning zero with an empty report. Keep diagnostics visible. DEP001–DEP005 were verified against native fixtures; review supported dependency definitions, source exclusions, ignores, package/module mappings and dynamic/plugin imports separately. A clean result does not establish that those project settings are complete.

- Python import structure = configure Import Linter for the project's actual importable packages and existing architectural boundaries, then retain `lint-imports --no-logo` with report `{ "type": "import-linter", "path": "coverage/import-linter.txt", "stdout": true }`. Run all contracts; `--contract` selection is rejected. The reader requires a fresh native text report with a nonempty graph, nonzero kept contracts, matching individual outcomes, no broken contracts and no warnings. It does not establish that configured roots or contracts cover the intended source. Review native ignored imports and type-checking exclusions under the existing exception policy. Import Linter 2.15's default acyclic-sibling depth is only ten; for each actual package use both its root and recursive wildcard as ancestors with depth zero, as below. Preserve additional layer/forbidden/independence contracts; do not invent them for a project without those boundaries. Standalone-script applicability and project configuration adaptation remain separate work.

```toml
# Replace mypackage with the actual importable package; include every applicable root.
[tool.importlinter]
root_package = "mypackage"

[[tool.importlinter.contracts]]
name = "No sibling dependency cycles"
type = "acyclic_siblings"
ancestors = ["mypackage", "mypackage.**"]
depth = 0
```

- Dart Decimate reports = retain `check . --threshold 0 --format json` with report `{ "type": "dart-decimate", "path": "coverage/dart-decimate.json", "stdout": true }`. The runner saves stdout separately from diagnostics and requires a fresh combined `dart-decimate.report.v1` check: no findings/clones, zero dead-code/duplication counts and threshold, and nonempty analysed source. A pass verdict alone is insufficient; native nonzero exits still fail. Verify actual entry points, exclusions, enabled checks and detection thresholds separately; these report assertions do not prove complete scan scope.

- Python duplication reports = retain jscpd's JSON report at `coverage/jscpd/jscpd-report.json` with report type `jscpd`. The runner requires fresh output, no duplicates, zero duplication counts and matching nonempty Python/total source, line and token counts. Native failures remain failures. Files below native detection thresholds can leave no analysed sources; that is not a pass. The report has no complete file inventory, so verify source inclusion, exclusions and detection limits separately. The supported JSON shape was verified with jscpd 5.2.0.

- Strict types = retain the native `types` check and Python annotation or JavaScript typing-lint check. TypeScript must run the explicit strict compiler flags, including JavaScript checking; preserve framework-specific typecheck commands as additional checks. Dart setup adds strict analyzer settings and type lints in `analysis_options.yaml`; PyYAML must be available to the runner's Python environment for native YAML validation. Relaxed settings, excluded Dart files and ignored Dart diagnostics fail; keep safe local inference. Verify existing includes and nested configurations after locked dependencies are available.
- Applicable checks = reuse the repository's build, integration-test and generator commands in the manifest. A committed generator must provide a check that regenerates affected outputs and fails on drift; use the generator's native check mode or the project's existing consistency command. Lockfile checks use the existing package manager and locked CI setup; do not reinstall dependencies after every edit.
- Parallel checks = mark a check `"parallel": true` only after confirming it is independent of adjacent checks and their outputs. The runner allows two in flight and refills a free slot immediately; unmarked checks are serial barriers, and lockfile setup always runs first and alone. Templates opt read-only checks in; test scripts, report-directory cleaners, generators, builds and heavy scanners remain serial unless their actual behavior proves independence. Report files must be distinct across checks. Account for each tool's internal workers before opting in expensive commands; this is a check limit, not a CPU or memory limit. Child output is grouped and displayed when that command finishes.
- Semgrep reports = retain `--error --strict --time --json` and a `semgrep` report path. Fresh JSON must show scanned source content and executed rules, with no findings, errors or reported skipped analysis. An empty scan or zero applicable rules fails. Verify actual security rules against safe/unsafe examples in each applicable language; report validation alone does not establish rule coverage or detect omissions hidden by native filtering.
- Deployment = when Docker/infrastructure configuration exists, add shared role `deployment`, command `["trivy", "config", "--exit-code", "1", "--format", "json", "."]`, and report `{ "type": "trivy", "path": "coverage/trivy.json", "stdout": true }`. Keep native stderr diagnostics enabled: no quiet mode or stderr suppression. The runner requires fresh schema-2 filesystem/config results with successful checks and no failures, incomplete statuses or reported suppressed findings; explicit successful-check lists must match their counts. It also rejects Trivy's logged errors and requires its scan-start diagnostic, because 0.74.0 can log a parse error while exiting zero and reporting only clean files. Native inclusion, severity filters and ignored findings still require separate scope/exception review.
- Container images = declare `container_images` when adapting a project and add role `container-vulnerabilities` using `osv-scanner scan image IMAGE --all-packages --format=json --output-file=coverage/image-osv.json` with report `{ "type": "osv-image", "path": "coverage/image-osv.json" }` for each produced image; build it before scanning and use distinct report paths. Native Docker-format archives can be scanned with `--archive`. The image reader retains OSV vulnerability/error checks and requires layer metadata plus valid package-to-layer origins; a source-only report cannot satisfy this role. Full image coverage remains unverified: OSV 2.5.1 silently omitted malformed npm installation metadata in a mixed archive, and its report does not establish the identity of the intended built image. Verify image selection and native extractor/exception coverage separately.
- UI checks = mark visual application packages with `ui: true` and provide a `ui` check for a small affected browser/device journey, including applicable accessibility assertions. Reuse the existing tests; JUnit reports can validate nonempty integration/UI runs without imposing unit-test coverage on that separate journey.
- React = add a `react` check using managed `react-doctor` with `--scope full --blocking warning --json --json-out coverage/react-doctor.json` and report `{ "type": "react-doctor", "path": "coverage/react-doctor.json" }`; it must scan the full applicable package. The runner requires fresh schema-3 output, React detected, no diagnostics/errors/skipped projects, and complete projects with no skipped checks and matching nonempty analysed-file inventories/counts. A successful exit or empty diagnostics alone is insufficient. Keep the native type check: React Doctor 0.9.13 reported a malformed JSX fixture as complete and clean while TypeScript rejected it. Verify configured project selection, rule filtering and exclusions separately. Keep Fallow's complete dead-code/duplication report and unlimited handwritten file size; exit status alone misses some duplication findings.

- Gitleaks reports = file and Git-history scans use separate `gitleaks` report paths with `--report-format sarif --report-path PATH --redact=100`. The runner requires fresh SARIF 2.1.0 with the Gitleaks tool identity, nonempty configured rules and no findings, preserving native failures. Empty findings are valid; missing/malformed reports are not. Native SARIF does not prove every file/commit was scanned or expose all exclusions, so verify actual scope and exceptions separately. Never echo finding payloads when reporting validation failure.
