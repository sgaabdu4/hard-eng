## Acceptance + steps

Design per item:
1. Secrets. `scan_git_history` is refused in any value but `true` (remove the key). The full check judges each line of the root `.gitleaksignore` (Gitleaks reads only that one): an entry passes only when a Gitleaks scan run now, with no ignore file, finds that exact fingerprint, and either (a) the entry names a commit (`<sha>:<path>:<rule>:<line>`) and the current-files scan finds no hit of that rule in that path, or (b) its path is marked `linguist-generated`. Gitleaks 8.30.1 reads a root `.gitleaksignore` even when `-i` names an empty folder, so the judge scans where no such file exists: the named commits only (`gitleaks git <bare shared clone> --log-opts=--no-walk <shas>`, the same fingerprints as a full scan) and one current-files snapshot with the file removed, reused for every entry. The judge runs in the full check after the tools are installed, and the history scan scope becomes `--log-opts=--remotes --tags HEAD` (HEAD, the remote branches and every tag, as CI fetches them). Each refused entry names its reason: stale, commit not in this clone (fetch it or remove the entry), still in the current tree, or not generated. Every other entry, a `.gitleaksignore` in another folder and every `.gitleaks.toml` allowlist stay refused.
2. Rust. `switch_off_pattern` gets a `.rs` pattern: `#[allow(`, `#![allow(`, `#[expect(`, `#![expect(`, `cfg_attr(…allow(` or `expect(`, and `#[ignore` (Proposal). The whole-project pass also refuses a Cargo `[lints]` or `[workspace.lints]` entry at level `allow` (Proposal).
3. Fallow. `fallow_failure` refuses a native Fallow command whose first analysis word is `dead-code`, `dupes`, `flags`, `security` or `similar-code` (the analysis subcommands of `fallow --help` 3.29.0 other than `health` and `audit`), the same first sentence as `--only`, naming the subcommand to drop. Another first word is a path for Fallow (`fallow architecture` fails with "PATH 'architecture' does not exist" in a folder without it), runs the combined scan with health, and is not judged by this item. The whole-project pass reads every `.fallowrc.json`, `.fallowrc.jsonc`, `fallow.toml` and `.fallow.toml` and refuses a `health` limit above `HEALTH_LIMITS`, a non-empty `health.ignore`, a `thresholdOverrides` entry above a limit, and a `complexity-*` rule not at `error`.

## Risks + recovery

- An Gitleaks entry check that runs Gitleaks makes the full check slower. Recovery: it runs only when a root `.gitleaksignore` has entries, scans only the named commits (P18: 17 commits in 2.9 s against 1,303 commits in 12.8 s) and reuses the current-files snapshot; the Stop hook does not run it.
- A history hit in Hard Eng or a project may be a live credential, which an entry would hide. Recovery: each entry is written only after the value is read locally; a live one stops the work and goes to the user to revoke. Hard Eng's hits look like digest values and test samples by their redacted context.
- A shallow clone or a fetch without tags cannot find an entry's commit, so a good entry reads as stale. Recovery: CI already fetches with `fetch-depth: 0`; the refusal names a missing commit apart from a stale one and says to fetch.
- A tag that only this Mac holds is scanned by the local full check but not seen by CI, so its hits fail locally and an entry for them would be refused in CI as a missing commit. Recovery: none in code; the tag is pushed or removed by its owner, never an entry. On this Mac 69 local-only tags hold 16 hits beyond the 9 entries.
- Moving Dart nested files to an include chain could let a nested file override a strict setting. Recovery: the merged settings run through the same typing check, and `false` rules and `ignore` errors stay refused in every file of the chain.
- A challenge can run forever on forms that text matching cannot stop. Recovery: a route that needs a forged tool is a stated limit and is listed in the row "Stated limits of the switch-off checks"; a finding is fixed when it is reachable by a plain line in a file the project owns.
