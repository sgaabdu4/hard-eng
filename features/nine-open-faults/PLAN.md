## Decisions + authorization

Blockers: None.
Handoff: Approval
Authority: Autonomous. On 13 November the maintainer said that the tool must be great and that the work stays in one session; the maintainer gave full authority for design choices earlier. Merge when the checks pass is a standing approval.

Decided:

1. 593: each read-only file listing of the hooks runs with the file watcher off, through one constant (`GIT_LISTING` in `.hooks/project_files.py`). Whole-tree compares keep the watcher: without it they are slower from about 10,000 files (plus 90 ms at 100,000 files). No hook command may rewrite the index. A project without the setting gets no added hook time. Rejected: one setting for the whole hook process, because it reaches the gate tools and the updater and slows whole-tree compares in large projects.
2. 590: the update is refused whenever the new release cannot load the project as the update leaves it. The check of the update PR runs the full load (`load_groups`), and the build step runs the same load with the code of the new release before the update branch moves. The refusal prints the rule text and one repair step, and the project stays on its release. The rule is strict: a project that already fails to load gets no update until it loads. Rejected: a load at the plan step, because it sees the tree before the update and gave a false refusal in a repro.
3. 589: the worktree launcher in a hooks folder inside the work tree stays a local file of the main checkout, and Hard Eng hides that one path in the shared `info/exclude` file. Hard Eng never changes a tracked hook outside a commit. Each update preparation first undoes what an earlier rerun left in the main checkout: it hides an untracked launcher, drops a launcher entry from the shell gate, and gives back a tracked project hook when the kept copy equals the committed hook. A tracked project hook that is not the present launcher is left as it is, with no note: a note would name a step that no command does, and it would show in each update status. Rejected: the update commit carries the files. A run showed that the installed updater refuses an update that touches an untracked path of the main checkout, so the checkouts with the fault could never update again.
4. 594: the message and the reference name an eager join that throws the first error at once with its own type: a small `waitBoth` helper that awaits `Future.wait` with `eagerError: true` and then reads each result. They no longer name a record's `.wait`. The reference states the plain form for two ordered steps that return values.
5. 596: the pause pass form of the Dart loop rule also accepts `await Future<T>.delayed(...)`, in the same three loop forms. Each new pass form names its exact call.
6. 595: the Fallow check sets aside a clone group when each instance of it is in a file with the generated mark. A group with one instance in hand-written code still fails. Setup writes nothing into the Fallow settings of a project.
7. 605: the delivered stage judges, for each required check, the run that the push to the base branch started. A run that another pull request started on the same commit is not read. A check with no push run is judged as before.
8. 606: `ship ready` reads the head checks before the review rule. A check that still runs gives a refusal that names the check and says to wait and run the stage again.
9. 607: the size of the inner run is not the cause. An inner run with workers shares the pytest temp root of the user. When it ends, it deletes the old temp folders that other pytest runs left there, inside its time limit: 72.7 s with 300,000 planted files, and 1.2 s on the next run. The fixture gives the inner runs their own temp root (3.8 s with the same planted files). No limit is raised. The outer `tests` gate pays the same delete when it ends, so the suite keeps the temp folder of a failed test only. One suite run with the old setting left 438,041 files (3.3 GB), and pytest keeps the folders of three runs.
10. Found during the build: the import order lint failed in each new checkout, because ruff sorted the `coverage` package by the presence of the untracked reports folder. The lint settings now name `coverage` as a third-party package.

## Risks + recovery

- 593: a whole-tree compare still asks the watcher: one ask in a quiet Stop and one in a new session start. When the watcher answers late, those two still wait. Measured with a watcher that waits 1 second for each ask: quiet Stop 2.2 s before, 1.2 s after; new session start 3.3 s before, 1.2 s after; session resume 3.3 s before, 0.2 s after.
- 590: a project that already fails to load, or one in the middle of its adoption, gets no update until its checks load. The build step runs in the installed code, so a background update gets that part one release later; the check of the update PR protects at once.
- 589: the exclude line holds in every worktree. In a linked worktree, a new `post-checkout` file of the owner in the hooks folder stays out of `git status` until the main checkout's file is no longer the launcher. A project whose own tracked `post-checkout` hook was replaced gets that hook back and loses the local chain, so its new worktrees get no Hard Eng preparation until the owner commits a chained launcher.
- 589: the three steps that write in a main checkout act only when the content equals what Hard Eng wrote or what the last commit holds; a test covers each refusal case.
- 605: one more API read in the delivered stage.
- Recovery: each repair is its own commit; revert that commit.
