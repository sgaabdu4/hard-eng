## Risks + recovery

- Released hooks may fail a Fallow health scan on the diagnostics notes that this branch added. Cheapest check: row 2's sealed run. If it fails, the update writes health, as the Decisions section says.

If a finding comes back, the case goes to the user before that project's PR, because a fix may need a history rewrite.
- After 0.0.76 clears the hold, a Dart repository that is not in the list, or new code merged after the scan, fails on released hooks. Recovery: the rescan just before PR 167 merges; a late failure gets a fix PR at once.

- A project's own `check:fallow` script keeps `--only` with no health after the update, and the new check refuses it. Recovery: its fix PR adds health; if the released hooks refuse that, the Hard Eng change of row 2, with a failing test first.
- Projects whose tests write lcov only may show every function as untested to Fallow, so CRAP fails in bulk. Recovery: the TypeScript health row; a Hard Eng fix before the release.
- Other sessions may work in the same repository. Recovery: the draft PR claim and the check of open PRs and sessions before work.
- Two builders at once may still load the Mac. Recovery: a fixed count of two; on a pause notice from the user, stop new work until the resume.
