# HE-YAGNI names operator content as stored data; one clear finding for a token file outside the app

Status: Complete

## Outcome + scope

HE-YAGNI says content that operators own and change (message text, dates, send windows, prices, audiences) is a current requirement for stored data, not code. The UI token reader reports one finding at a CSS `@import` that points to an existing CSS file outside the app, when the import is added or when it causes undefined-token or `DESIGN.md` weight findings, and drops those findings. The shared rules line for a failing check says that Hard Eng is strict and is broken only when no project change passes, with no more tokens than before. The check no longer takes a verified update that changes a project rules file as proof of the project's own checks, and CI no longer skips the shared checks for a change to a root file that is not documentation, so a root `AGENTS.md` change in an update runs them. A mockup that `look` opened in the pushing checkout counts in the pre-push copy of the plan check, because the check reads the record folders of every worktree of the repository. Hard Eng's own files fetch URLs through one https-only opener, and the Flutter example no longer holds a literal insecure websocket address, so the default Semgrep rules stay quiet on them. A Flutter `.arb` localization file counts as a native change, so a Flutter-only app that changes `.dart` and `.arb` files needs a native Before and After pair, not a browser capture. Non-goals: following or accepting the outside import; the planning case that the issue suggests; package import forms.
