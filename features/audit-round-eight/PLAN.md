# Make the hooks faster, give each PR a before and after part, and fix the faults that real projects found in the round 8 audit

Status: Complete

## Outcome + scope

A Stop after a source change starts fewer Git commands and fewer tool lookups, and takes less time. A check of a React app does not wait 30 s at the end of each React Doctor scan, on a machine that has Node. `ship` refuses a PR text that has no before and after diagrams, and the ship reference says how a PR text is written. A small change needs no plan, also when the base branch holds an open plan. Each fault that the round 8 audit reproduced in a real project gets a fix. Five ways to switch a check off in a source file, which passed, are refused. The shared rules file tells each agent that the codebase is its own, so that it merges repeated code and fixes faults in the code that it changes.

The bar for this round: build a fix for a wrong pass, a wrong fail, a printed step that fails, a state with no way out, or a slower hook. Fix minor wording only where its owner file is open for another fix.

The round 8 audit ran six auditors in sealed copies of the released code. Four of them used real public projects: two Python libraries, one Dart package and one TypeScript action.

Non-goals:

- Design choices, not built in this round; on 2026-11-11 the maintainer gave these decisions to the coordinator, and round 9 decides and builds them. (a) The comment rule makes a change clean each old comment block of a file that it touches; in the three real libraries the first edit of an old file named 4 to 80 old blocks, and some of them are public documents (`///`, `#:`). (b) Findings of Dart Decimate, Fallow, React Doctor and Trivy cannot become adoption debt; the real Dart package could not finish `adopt` for that reason. (c) The quick secret scan at Stop reads each current file; a scan of only the changed files is faster and has a smaller scope.
- For round 9, which gets its own plan: a change can weaken a check through a settings file and still pass. The audit showed four forms: a Ruff ignore list in `pyproject.toml`; a `linguist-generated` mark on a hand-written file; a narrower gate command in `hard-eng.gates.json`, which the printed `adopt` step then locks in; and an edit of an installed `.hooks/` file. These need one design, and the last one may be a maintainer choice.
- Also for round 9: a repair branch that is checked out in its own worktree makes each update report "failed" when no release is newer (`branch_current` in `.hooks/update_runner.py`); the fix is in the update code and needs its own real run first. After `git push --no-verify`, Stop reports no change since the session base. The push check reads the shipping policy of the checkout and not of the pushed commit. A failed fetch of the update sources gives the plan refusal with no line about the fetch. After a rename with a stale `--cov=` value, the tests gate names only the missing report file. The push check drops Git settings that the caller gives through `GIT_CONFIG_COUNT`.
- Speed work that was measured and is not built in this round. One Stop of a new Vite app after a source edit takes 4.1 s, with 93 Git starts. Left for round 9: the second start of each check through `uv run` (80 ms in the Python fixture, 233 ms in the Vite app); three `tsc --showConfig` runs in each Stop of a project with three tsconfig files; one file listing for each Biome gate; about 230 ms of imports; the Stop process before its check (0.3 s in the Vite app). Hard Eng also keeps one full tool set for each checkout (about 400 MB) until the checkout is gone.
- The TypeScript action could not be adopted because of its own state: 6 tests fail on this machine, and its bundled output holds strings that the secret scan reports. Secrets are never debt.
- Carried from round 7, not built: the removed-test rule is a net count and does not follow a test that moves to another file; a child process of a test can still reach a real host; `--new python` adds pytest with no release wait; one removed `node_modules` folder of a workspace member does not end the root's install mark; a Stop in the update worktree with a changed tree proves the update over the network; the weaker tests that the round 7 test review named.
- Minor: a Sphinx `docs/` folder counts as Python source for the dependencies gate.

## Decisions + authorization

Blockers: None.
Handoff: Approval
Authority: Autonomous. On 2026-11-10 the maintainer told the builder to run the audit and fix rounds autonomously and to follow Hard Eng and Learn. On 2026-11-11 the maintainer said that speed is very important, asked for tests on real projects, and asked for the PR form of slice 4.
Decided (1): one check process asks Git for the common folder one time. The folder cannot change while a process runs.
Decided (2): in the current-files scan, a linked folder of the same repository takes its paths from the listing of its repository root. That listing is made at scan time, as today. A submodule keeps its own listing. The scan reads the same files as before.
Decided (3): a quick check reuses the scanner versions that the last lookup stored for the same cutoff hour. A full check always looks up and stores. A new cutoff hour or a missing store ends the reuse. The store is one file in the tool folder that all checkouts of the machine share (the folder above `checkouts`), as uv's own cache is shared, so a full check of another checkout also renews it. A stored value that is no plain version number is dropped at the read. When uv's cache lost a stored version, the quick gate fails with uv's text, and the check adds the "not installed" message that names the full check.
Decided (4): one `check` call resolves the release references, the branch point and the revision of a reference one time. Nothing is kept outside a `check` call, because `update` and `ship` move references inside one process.
Decided (5): the rules that run before the first tool of a check share one list of changed files for one base and one list of plan files. Nothing is kept across the gates, because gates and installs write files. The skip rule after the gates lists again.
Decided (6): the quick secret scan keeps its scope. A scan of only the changed files is named for the maintainer with the measured gain.
Decided (7): a change that changes no plan and that the size rule calls small needs no plan, also when the base holds an open plan. Stop, `check`, a check with a given stage and the push check then print the size line and pass. A big change with no plan of its own is still judged by the open plans, and a branch that edits a plan is judged by that plan. The size rule runs only inside `check`, and only when the branch changes no plan, so a build that changes its own plan starts no new Git command. Stop asks no size question of its own: it reads the size line of its check and then does not report a build in progress or an unfinished plan. A Stop in a later session of a build, where the session changed no plan, keeps its cost; the count test holds that state. Stop's own plan notice does not block for an unfinished Draft plan that the branch did not change, when the session changed no plan; it asks Git for the plans of the branch only in that state. This holds for a plan that a remote base holds; in a project with no remote base each plan is the branch's own, and Stop blocks as before. In the worktree of the update branch, with a change and an open plan on the base, the size rule asks the update proof, which is one network call; one `check` call asks it one time. The proof decides the result there: with it, a small fix on the update branch passes, and without it the open plan judges the change.
Decided (8): the line limit message names three ways: split the file; mark generator output with `linguist-generated=true` in `.gitattributes`; or record a `file_size_exceptions` entry with a reason and evidence in `hard-eng.gates.json`.
Decided (9): the Dart classifier takes a class of any kind whose members all emit no counter. A real run showed that a concrete class with only `static const` fields gets no coverage entry, also when a test calls its implicit constructor. An explicit generative constructor, an instance field or a method with a body still needs coverage.
Decided (10): the text of HE-COMMENT-LINES says what the code does: the exemption for old blocks holds in the change that installs Hard Eng. The rule itself does not change; non-goal (a) names the choice.
Decided (11): setup refuses a lockfile path that Git ignores also when the file is not there yet. The config load tests only the lock file of the group's own lockfiles gate, and refuses it when it is on disk and Git does not list it; the name comes from the first word of that gate's command, by one map that setup also reads. A lock file of another manager, and a group with no lockfiles gate, are not tested. Both use one message; when the file is not on disk yet, its step says to run the install before the commit. The load uses the file listing that it already holds.
Decided (12): the debt form of a line writes the folder part of a Hard Eng rule name in one stable form, found by the literal `hard-eng-rules.` part of the name. `adopt` writes that form into the debt file. A record that a machine wrote with its temp folder still matches, because recorded and current lines pass through `neutral`.
Decided (13): `uv_rows` reads a tree whose root line has no version, as uv prints for a project with a dynamic version.
Decided (14): the freshness target of a uv project is the newest release that passes the release wait and is not newer than the version that uv itself names as latest. uv's answer obeys the project's Python range, so the printed `uv add` step can be done. uv's answer alone is no target, because uv applies no release wait to it. The Python requirement of a release below uv's latest is not read: in the rare case that such a release needs a newer Python than uv's latest does, the target cannot install until uv's latest passes the wait (two days at most).
Decided (15): when a debt form holds recorded and new lines, the failure adds one hint: run the gate's tool on the files of this change to find the new ones. The debt file holds neutral forms, so the code cannot name the new line itself.
Decided (16): the debt form makes each run of spaces one space, so the padding of a line number column cannot make an old finding new.
Decided (17): a `ruff check` gate runs with `--no-fix`, added at run time, so each installed project is covered with no change of its gates file. A check then never writes source files through ruff, and a fixable finding fails the gate. In the adopted real Python project, which sets `fix = true`, the lint, complexity and annotations gates matched their recorded debt with the flag and without it (2,583 recorded lines, no new form and no lost form).
Decided (18): the missing performance suite refusal is read only from the output of a gate with the `performance` role.
Decided (19): the ship reference gets a "PR text" contract. Each PR text has headings, sections and bold lead words, in plain simplified English. It has a "Before and after" part: one Mermaid diagram of the old flow and one of the new flow for each main change, or two or more diagrams of the new flows when no old flow exists. A UI change shows before and after screenshots with a red ring on each changed thing, and a video of the whole flow when stills cannot show it. `ship --stage ready` refuses a PR body with fewer than two Mermaid blocks. The Hard Eng update PR keeps its generated text; it does not pass through `ship`.
Decided (20): HE-OUTPUT-PLAIN now covers PR texts and the other text for people (replies, release notes), and it says which style the text for agents keeps. The PR text contract of Decided (19) gives the structure.
Decided (21): React Doctor runs on Node when Node is installed, as wrangler and miniflare do. The stand-in that runs Node tools on Bun (`bun_node`) gets that route. The same tool file with a real scan took 31.5 s and 32.5 s on Bun and 2.6 s and 2.8 s on Node. The telemetry switch (`REACT_DOCTOR_NO_TELEMETRY=1`) is not set: six checks with the switch still took 31 to 33 s for each real scan. A machine with no Node keeps the wait. React Doctor is a tool of the check and not code of the project, so the project's own scripts still run on Bun.
Decided (22): the debt form drops Biome's summary line ("Some errors were emitted while running checks", "Some warnings were emitted while running checks") from recorded and current lines, as it drops code frames. A project that fixes its old warnings then passes with no new step.
Decided (23): the moved-source message says add, or replace the old name when a file moved. The tsconfig message also names an `exclude` entry that matches the file. The "CI setup pending" line is not changed here: in a setup rerun the code reads the base branch from a temporary copy and never sees the gates file of the checkout, so it cannot tell the two states apart without a larger change. That line is on the list for round 9.
Decided (24): the switch-off rule refuses each comment form that Ruff's documents name: `noqa` in any case, `# ruff: noqa`, `# flake8: noqa`, `# ruff: ignore[`, `# ruff: file-ignore[`, `# ruff: disable[`, the isort skip and off comments, `# fmt: off`, `# fmt: skip` and `# yapf: disable` (Ruff's formatter also honours the last one). It refuses `# pyre-ignore` and `# pyre-fixme`, and the strict Pyrefly rule refuses `permissive-ignores = true`. It refuses the Bun and Vitest forms `todo`, `failing`, `fails`, `if` and `runIf` of `test`, `it` and `describe`, also behind the modifiers `concurrent`, `sequential` and `shuffle`. A full-line comment is not an assertion line.
Decided (25): a `Retro:` or `Same cause:` value of bare `None` needs a reason, as a not-applicable value does. A `path::test` name in either value must exist, by the rule that acceptance lines use: on the first line and on the lines that follow it up to the next field. The refusal names the line that holds the name. The words of a retro stay a matter for review.
Decided (26): the shared rules file tells each agent that the codebase is its own, by the maintainer's request of 2026-11-11 (the sentence "This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it."). The purpose: in each installed project an agent merges repeated code, moves code to its owner and fixes faults in the code that it changes, each as one commit, and does not add new code beside the old structure. The sentence joins the old owner line in one line; optional improvements and extra infrastructure still need a request. The file stays inside its size limit of 3,921 bytes (3,911 now, 3,882 before): two lines lose text that setup prints or enforces at the moment of need. The line about old rules files keeps a short standing form, and the message of setup names the full steps. The gap line no longer repeats the command or the privacy rule, because setup prints the command and the command refuses project text. An update replaces the rules block of an installed project, so each project gets the line with its next update. A new model check case, `repeated-block`, measures the rule: a small feature beside two copies of one parsing line, judged by the feature, the check and one owner of the parsing. It runs for three rule texts on the same hook code: the old text, the sentence alone, and the final line. Known cost: the source of the sentence reports about 1.5 times the output and changes that nobody asked for; a project that wants the smallest change can state that in its own rules below the shared block.
